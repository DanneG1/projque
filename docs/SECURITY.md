# Security

Projque interacts with local files and launches external applications, so its security model is deliberately small enough to explain on one page.

## Threat model

Untrusted inputs:

1. **README/ROADMAP content** - markdown from cloned repositories may be hostile.
2. **File and directory names on disk** - may contain shell metacharacters, quotes, unicode tricks.
3. **A compromised webview/renderer** - if the UI process is somehow subverted, it must not be able to read arbitrary files or run arbitrary programs through the backend.

Out of scope: a malicious local user (they already have your shell), and a maliciously edited `settings.json` - editing it is the same trust level as editing your own `~/.zshrc`. The point of the design is that the *renderer* can never reach what settings.json can.

## Invariants

### 1. No paths or shell strings cross the IPC boundary

Every command takes opaque IDs (`project_launch(id, action)`) or closed enums. Folder pickers run in Rust; scan results are returned with opaque candidate IDs and imported by ID. `AppState::resolve_dir` is the single ID→path resolver (canonicalize + directory check).

### 2. No shell, no arbitrary command execution

- `tauri-plugin-shell` and `tauri-plugin-fs` are not present.
- All processes are spawned with `std::process::Command` and argv arrays - no shell interpretation anywhere, so file names with `;`, `$()`, quotes etc. are inert.
- Launchable programs come from the static allowlist in `launcher/catalog.rs`. The frontend can only select a `kind` from it.
- Embedded agent sessions run the allowlisted agent binary **directly on a PTY - never through a shell**; cwd is the resolved project directory, and the environment is the app's own plus an augmented PATH. Session IDs are opaque backend-generated tokens. Run sessions (dev servers etc.) use the same PTY-not-shell spawn.
- The one place a shell script is *generated* (not fed user input from the frontend): the macOS `.command` file used to run an agent in Terminal.app/iTerm2, because those apps have no "run command" flag. It is written with mode 0700 into the app's own cache directory, contains only Rust-canonicalized, single-quote-escaped values from the catalog, and is pruned after an hour. The alternative (AppleScript) needs the Automation permission and double escaping - strictly worse.

### 3. No automatic network

- No HTTP client exists in `Cargo.toml` or `package.json`; no `fetch` in the frontend.
- CSP (`src-tauri/tauri.conf.json`): `script-src 'self'` (no `unsafe-inline`, no `unsafe-eval`), `connect-src 'self' ipc: http://ipc.localhost`, `frame-src http://localhost:* http://127.0.0.1:*` (only so the **Preview** pane can show the user's own dev server next to its terminal - the framed page is a different origin and cannot reach the app, the app never scripts into it, and the `src` is the backend-detected localhost URL re-checked against a `localhost`/`127.0.0.1` pattern in the frontend; nothing else may be framed), `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`; and the asset protocol is disabled. (Prototype freezing is left off: the embedded terminal library assigns to inherited properties like `toString` on its namespace objects, which a frozen `Object.prototype` forbids. The CSP - no eval, no inline/remote scripts - is the primary defense; prototype-pollution hardening is a defense-in-depth layer we forgo for terminal compatibility.) The one relaxation is `style-src 'self' 'unsafe-inline'` (required by the terminal and markdown renderers) - it permits CSS injection but no script execution and no network egress.
- Network egress is limited to a small, enumerated set of commands, each of which contacts only a host **you** supplied (a git remote, a clone URL) or opens your browser: `git fetch --prune`, `git pull --ff-only`, `git clone`, `git push -u origin HEAD` (Push button and publish flow - explicit click, never forced), `gh repo create --push` (publish flow: public; "Back up to GitHub": `--private`, same secrets gate), `gh pr view`, `gh repo view` / `gh api repos/…/pages` (publish flow only), and `open_external_url` (browser navigation to an `http`/`https` URL). The publish flow additionally runs a secrets scan (`github/secrets.rs`) over everything a push would make public and refuses to publish while it finds credential-shaped content - checked in the UI *and* re-checked inside the backend command. `git_sync` (Commit & push) chains `pull --ff-only` and `push -u origin HEAD` behind one explicit click; when the project's own pipeline files say a push to the current branch deploys (GitHub Actions `on: push`, a Vercel/Netlify/Render config - `project_deploy_info`, read-only detection), the UI adds a second confirmation step before that click. `project_audit_run` (Check packages) runs the project's own package manager's `audit --json` (npm/pnpm, fixed argv, headless, 180 s timeout) - this sends the dependency tree to the package registry's advisory endpoint, on an explicit click (the "Health check" button on the projects page runs it for every supported project in turn, one at a time, behind the same single click - optionally preceded by `git fetch --prune` for every project with a remote, and followed by each project's test command as an ordinary run session) (and once more automatically when an "Update safely" run started by that click finishes, so the numbers reflect the result); "Update safely" is `npm audit fix` (never `--force`) as an ordinary visible run session with the enumerated target id `audit:fix`, so it installs fixed versions from the registry exactly as running it in a terminal would. Four more spawns can reach the network indirectly: `git_change_summary`, `git_commit_message` (a one-line message for the commit box), `transcript_summarize` (a recap of a saved session transcript) and `session_explain_error` run the user's own `claude` CLI headless (`--print`, fixed argv) - the same allowlisted binary and trust level as an embedded agent session. The change summary fires on an explicit click, and once automatically when an embedded agent session ends with uncommitted changes (the post-session review card) - the agent session that just ran is the larger, already-consented use of the same account; the explanation fires on click only. In normal use these fire only on an explicit click. Note the boundary honestly: **the click is a UX convention, not a security control** - under the compromised-renderer threat model these commands are reachable from the webview without a click. What they cannot do is reach an *arbitrary* capability: the destination is always a host you configured or a scheme-allowlisted URL, argv is fixed, and there is no general HTTP client. `gh` is your own installed, authenticated binary, invoked with fixed argv exactly like git. These run with `GIT_TERMINAL_PROMPT=0` and SSH `BatchMode`, so they require non-interactive credentials (ssh-agent or a credential helper) and can never prompt.
- All other git usage is local-only: read subcommands (`status`, `log`, `config --get`, `for-each-ref`, `ls-files`, `rev-parse`, `diff`), `switch`, `add`/`commit`, and the snapshot/restore plumbing (`write-tree`, `commit-tree`, `update-ref`, `read-tree` - see §6); none touch the network.
- Verify yourself: run Projque with Little Snitch/`nettop` open, or offline - everything except the Fetch/Pull buttons works, and those fail cleanly.

### 4. Filesystem scope

- Scanning touches only user-configured roots, depth-capped, and **never follows symlinks** (`walkdir` with `follow_links(false)`).
- Document reads are confined to imported project directories; a configured roadmap path is canonicalized and must still resolve inside the (canonical) project dir, which also defeats symlink escapes. Reads are capped at 512 KB.
- Agent session transcripts (`transcript.rs`) are written to `<config dir>/transcripts/<project id>/` - the app's own folder, never the project (they may contain whatever the agent printed, including secrets it read). Listed and deleted by validated file name only; at most 30 per project.
- Reclaim disk space (`project/disk.rs`) is the one command that deletes user files, and it can only delete directories whose *name* is on a fixed allowlist of regenerable folders (`node_modules`, `target` next to a `Cargo.toml`, `.next`, `__pycache__`, `.venv`, …), found by the backend's own scan at most four levels deep, never through symlinks, never inside `.git`, and re-verified at delete time to be a plain directory inside the project. The frontend supplies display keys from that scan, not paths.
- The live git refresh (`watch.rs`) watches imported project directories with the `notify` crate (FSEvents on macOS, recursive; only `.git` elsewhere). It is read-only: an event carries the opaque project id to the frontend, which re-reads git status through the existing command. Nothing is executed on an event and no path leaves the backend.
- Config writes are atomic (tmp + rename); an unparseable config is renamed to a `.bak`, never deleted or overwritten.

### 5. Markdown is rendered inert

`src/components/MarkdownView.tsx` is the only renderer:

- react-markdown builds a React element tree; raw HTML is dropped (no `rehype-raw`, no `dangerouslySetInnerHTML` anywhere in the codebase).
- `rehype-sanitize` runs as defence in depth.
- `urlTransform` allowlists `http/https/mailto`, killing `javascript:`, `data:`, `file:`.
- Images are never loaded (asset protocol disabled) - alt text renders instead.
- Links open only via the audited `open_external_url` command.

### 6. The audited exceptions

A small number of commands accept more than IDs/enums, on purpose, and are the places to review hardest:

- **`open_external_url(url)`** - free-form string, validated in Rust: ≤ 2048 chars, scheme must be `http`/`https` (allowlist, not denylist), no whitespace/control chars, then handed to the OS browser. It can only ever cause a browser navigation.
- **`git_switch(id, branch)`**, **`git_branch_delete`**, **`git_merge_into`** - the branch name is a frontend-supplied string, validated by exact byte match against a fresh enumeration of the repository's own `refs/heads`, re-run backend-side at call time - the value provably names an existing local ref, so option/command injection is impossible (leading `-` and control characters are rejected as defence in depth). `git switch` itself refuses to clobber uncommitted changes; the app never passes `-f`, `--discard-changes`, or `-m`; branch deletion is `-d` only (refuses unmerged work). Merge (`git_merge_into`: the current branch is merged into the validated target after switching to it) requires a clean tracked working tree (so abort provably returns to a known-good state), never passes `-f`/`-X`, and on conflicts stops: the only exits are `git_merge_complete` (which refuses while any conflicted file still contains conflict markers) and `git_merge_abort`. The mutating git verbs are limited to `fetch`, `pull --ff-only`, `switch`, branch create/safe-delete, `add -A` + `commit`, merge as described, the restore sequence below, and `push -u origin HEAD` - rebase, reset, clean, stash, and forced anything are excluded by design.
- **`project_env_set(id, key, value)`** - `key` must match `[A-Za-z_][A-Za-z0-9_]*`; `value` (control characters stripped, ≤ 4096 chars) is written as one `KEY=value` line into the fixed-name `.env` directly inside the project (refused if `.env` is a symlink or not a plain file), replacing that key's line and preserving the rest. Values are only ever read back masked. `.env` content never goes to any command.
- **`settings_prompt_save(id?, label, prompt)`** - free-form strings (label ≤ 60, prompt ≤ 4000 chars, control characters stripped) stored in settings.json; a saved prompt is only ever used as an agent session's `initial_prompt`, the already-audited path with the same trust as typing into the session.
- **`experiment_start(id, label)`** - the label is a frontend-supplied string: trimmed, control characters stripped, 200 chars max; it is slugged to ASCII letters/digits/dashes for the `try/<slug>-<stamp>` branch name (then validated exactly like `git_branch_create`) and otherwise only ever becomes a single `-m` argv element ("Try: …" / "Abandoned try: …"), like a commit message. `experiment_discard` is the one place `git branch -D` runs: only on the app-created try branch, and only after its tip has been pinned under a `refs/projque/snapshots/` ref, so nothing becomes unreachable - it is a rename of where the work lives, not a deletion.
- **`git_branch_create(id, name)`** - the branch name is a frontend-supplied string: strict charset validation in Rust (alphanumeric start; letters, digits, `.`, `_`, `-`, `/`; no `..`, `//`, trailing `/` or `.lock`; ≤100 chars - which excludes options, whitespace, control characters and revision operators), then `git check-ref-format --branch` as the final authority before `git switch -c`.
- **`git_commit_diff(id, hash)`** - same hex-only + `rev-parse --verify` validation as `git_restore`; read-only (`git show`). Diff file paths returned to the UI are repo-relative names from git's own output, used for display only - they are never accepted back as input.
- **`git_commit(id, message)`** - the message is a frontend-supplied string (≤1000 chars, control characters except newline stripped) that is only ever the *value* of `-m`, one argv element - git cannot parse it as an option and no shell exists to interpret it.
- **`git_restore(id, hash)`** - the hash is validated to 7–40 hex characters (which excludes `-`, so it can never be an option, and excludes revision-expression operators), then resolved with `git rev-parse --verify <hash>^{commit}` - it provably names a commit object in this repository. Restore is additive by construction: the current working tree is first snapshotted to a hidden ref (`refs/projque/snapshots/…`, built in a scratch `GIT_INDEX_FILE`, never pushed, never touching the user's branch/index), then `read-tree -u --reset` + a NEW commit lands the old state on top of history. No history rewriting exists in the codebase.
- **`idea_set_done(id, line, done)`** - a positional line handle into IDEAS.md, re-validated against the current file content before the single-character checkbox rewrite; a stale handle fails as a conflict instead of writing.
- **`doctor_fix(kind)`** - closed enum of fix kinds; each maps to a fixed program + argv chosen in Rust (currently `gh auth login` in the user's terminal). The frontend cannot influence the command.
- **`run_session_start(projectId, targetId)`** - the target is validated by exact match against a fresh enumeration of the project's **own manifest files** (package.json scripts, Cargo.toml, go.mod, csproj), re-derived backend-side at launch time; the runner comes from a static table and the argv is built in Rust. Be clear about what this means: running a target executes that project's own code - a user-initiated decision with exactly the trust of running `npm run dev` in your own terminal (and the same trust as launching a coding agent there). The "Open in browser" button opens only a URL the run itself printed, stored backend-side, restricted to localhost hosts - no URL crosses IPC.
- **`agent_session_write(sessionId, data)`** - free-form bytes into the stdin of a PTY running an allowlisted agent in one of the user's own project directories (64 KB/call). Framed honestly under the compromised-renderer model: this is stronger than "typing into Terminal.app" - the renderer can write to *any* running session, scripted and without a visible keystroke. This is inherent to the embedded-agent capability (a compromised renderer can equally `agent_session_start` its own agent in any imported project); the residual risk is that a subverted webview has the same reach over your agents as you do. It cannot spawn anything outside the agent allowlist or outside an imported project directory.
- **`project_update`'s `productionUrl`** - free-form string, shape-validated like `open_external_url` (http/https scheme allowlist, no whitespace/control, ≤2048); stored as project metadata and only ever opened through the audited `open_external_url` path.
- **`project_create(name, description, …)`** - `name` is restricted to `[A-Za-z0-9._-]` starting alphanumeric (max 100; it is also the directory name); `description` becomes file content (README) only, never an argument. **`project_clone(url, …)`** - the URL is shape-validated (https/http/ssh/git@ prefix - which also excludes a leading dash - no whitespace or control characters, ≤300 chars) and passed to `git clone` as a single argv element after `--`, so it can never be parsed as an option. **`agent_session_start`'s `initial_prompt`** - content handed to the user's own agent as one positional argv element (≤4 KB), the same trust level as typing into the session. **`agent_session_start`'s `session_label`** - display-only text (trimmed, control characters stripped, ≤80 chars) used as the session's pane/list label and notification title, e.g. a roleplay-tester persona name; rendered as React text nodes only, never an argument or path.
- **`git_restore(id, hash, discardNew)`** - `discardNew: true` (the review card's "Undo session") additionally stages untracked files before `read-tree --reset`, so files the agent created are removed too; the pre-restore snapshot (which captures untracked files) is still taken first, so this remains additive. **`git_ignore_fix(id, kinds)`** - `kinds` are ids from a closed catalog in `git/hygiene.rs`; the `.gitignore` lines appended are the catalog's own fixed patterns, never frontend text, and a symlinked `.gitignore` is refused. `git_commit` (and therefore `git_sync`) refuses while the secrets scan finds credential shapes in the files the commit would add - the same scanner as publish, applied to `git status` paths. Documentation example keys and fixture-shaped strings (`…EXAMPLE`, `0123456789abcdef…`, `XXXX…`) are not findings. A boolean `allowSecrets` lets the user override a false positive after an explicit checkbox ("I checked - this is not a real secret") - a local commit is not publication, and publish keeps its hard block with no override.
- **`roadmap_set_done(id, line, done)`** - identical pattern to `idea_set_done` (positional line re-validated as a checklist item before the rewrite), on the project's roadmap file as resolved by `find_doc` (containment-checked). **`project_mark_verified(id, passed)`** - a boolean; the timestamp is stamped in Rust.
- **`session_explain_error(sessionId)`** - takes only an opaque session id; the text explained is the tail of that session's own scrollback, read backend-side (ANSI-stripped), so no terminal text crosses IPC inbound. The returned excerpt may come back in via `initial_prompt` ("ask the agent to fix it") - the already-audited path.
- **`idea_capture(id, text)`** - free-form text (≤4 KB, control characters except newline stripped) appended as file *content* to a fixed-name `IDEAS.md` - in the project directory named by the opaque id, or (with `id: null`, a "general" idea) in the app's own config directory. The name is not frontend-supplied, the path is built in Rust, and an existing `IDEAS.md` must canonicalize to a regular file inside the (canonical) project directory - the same symlink-escape rule as document reads, applied to the write side. The text is never an argument to anything; worst case under the compromised-renderer model is markdown appended to this one file in an imported project.
- **Hand-edited `command`/`args`/`pathAdditions` in `settings.json`** - honored, exec'd as argv without any shell. Reachable only by editing a local file, never from the UI or webview.

### 7. Child processes

Embedded agent sessions are child processes of Projque: closing the app closes the PTY, which delivers SIGHUP and ends them (the app warns before quitting while sessions run). Residual risk: a child that ignores SIGHUP could outlive an app *crash*; there is no daemon or pidfile reaper in this version.

### 8. No telemetry

There is no analytics or telemetry code of any kind.

## Reporting

Open a GitHub issue for non-sensitive reports. For anything sensitive, contact the maintainer privately (see the repository profile). No bounty program; best-effort response.
